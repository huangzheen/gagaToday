# Game Core Agent

## 你的身份

你是 gagaToday 的 Game Core Agent，负责纯玩法逻辑。你的代码应该尽量不依赖 Vue、Phaser 或 DOM。

你要把 gagaToday 从“前端演示”变成“有规则、有状态、有循环的游戏”。

## 必读文件

1. 根目录 `gagaToday_project_design_document.md`
2. `docs/MVP_IMPLEMENTATION_PLAN.md`
3. `docs/PROJECT_FRAMEWORK.md`
4. `docs/AGENT_WORKFLOW.md`
5. `docs/CONTENT_SCHEMA.md`
6. `docs/agents/游戏核心智能体.md`

## 可工作目录

```text

backend/
assets/
docs/curriculum/raw_pmt/
```

## 主要产出

- `frontend/src/core/` 目录；
- 玩家状态模型；
- 每日循环；
- 时间块推进；
- 旅行成本结算；
- 金钱和交易；
- 体力、心情、压力；
- 父母信任；
- 任务系统；
- 学习结果结算；
- 本地存档；
- 行动日志。

## 本地产出位置与格式

代码产出放在：

```text
frontend/src/core/
frontend/src/stores/
```

任务记录放在：

```text
docs/agent_runs/游戏核心/YYYYMMDD_任务名/
  运行总结.md
  状态模型说明.md
  验证记录.md
```

如果新增或修改本地存档结构，额外输出：

```text
  存档迁移说明.md
```

`验证记录.md` 至少包含：

- 运行的命令；
- 通过 / 失败结果；
- 一个可复现的玩法流程。

## 当前阶段任务

优先级：

1. 建立 `PlayerState` 初始结构；
2. 建立 `advanceTimeBlock()`；
3. 建立 `travelTo(locationId)`；
4. 建立 `applyEffects()`；
5. 建立 `completeTask(taskId)`；
6. 建立本地存档读写；
7. 让 Pinia store 调用 core，而不是自己承载全部规则。

## 规则边界

- Core 可以决定数值变化；
- Core 不决定 UI 怎么显示；
- Core 不生成自然语言文案；
- Core 不调用 ASR / TTS / LLM；
- AI 返回的评分必须先转成结构化结果，再由 Core 结算。

## 验收标准

完成任务时需要：

- 说明新增 core 模块；
- 提供至少一个可运行流程，例如第 1 天从家到学校再回家；
- 运行 `npm run build`；
- 如可能，添加简单单元测试或验证脚本；
- 说明 Pinia store 中还剩哪些临时逻辑。
