# 1. 项目定位

**gagaToday** 是一款以德国留学生活为主题的像素风生活模拟 RPG。

玩家扮演一名中国学生，初三毕业后前往德国学习和生活。游戏通过真实德国城市、真实生活成本、语言学习、课程学习、社交关系、兴趣探索、账单事务和家庭沟通，模拟一个学生从“刚到德国什么都不懂”到“逐渐适应、成长、建立关系、规划未来”的全过程。

本项目不是传统教育 App，也不是单纯剧情游戏，而是：

> **真实德国留学生活模拟 + 语言学习 + A-levels / 国际课程学习 + 开放地图探索 + AI 语音互动 + 数据驱动内容扩展平台。**

# 2. 项目背景与市场机会

## 2.1 传统留学准备存在痛点

留学前学生和家庭通常面临以下问题：

- 信息碎片化；
- 对真实生活认知不足；
- 对德国学习、交通、账单、餐饮、社交场景缺乏体验；
- 语言学习与真实生活场景脱节；
- 家长难以判断孩子是否具备独立生活能力；
- 传统留学服务更偏申请流程，较少覆盖“到达后的真实生活”。

## 2.2 语言学习缺少沉浸式环境

传统语言学习往往停留在：

- 背单词；
- 刷题；
- 课堂对话；
- 模拟考试。

但真正到了德国，学生需要面对：

- 点餐；
- 问路；
- 看懂账单；
- 看懂学校邮件；
- 与同学交流；
- 跟老师沟通；
- 处理交通、银行、保险、手机套餐等事务。

这些真实场景很难通过传统课程完整覆盖。

## 2.3 年轻用户更接受游戏化学习

13-25 岁用户对以下形式接受度较高：

- 像素 RPG；
- 成长养成；
- 任务系统；
- 成就系统；
- 地图探索；
- 社交关系；
- 模拟经营；
- AI 角色互动。

因此，gagaToday 的机会在于：

> 把“留学前的抽象焦虑”变成“可体验、可学习、可规划”的游戏化过程。

# 4. 核心产品概念

## 4.1 核心体验

玩家每天都要在有限资源下做选择：

- 今天是复习还是出去探索？
- 是省钱吃食堂，还是和同学去餐厅？
- 是买博物馆门票，还是留钱买教材？
- 是周末去球场，还是准备数学测试？
- 是练德语口语，还是赶 A-levels 作业？
- 是自己做饭省钱，还是外出吃饭提高社交？

核心张力来自：

> **有限的钱、有限的时间、有限的体力、听不懂的语言、必须完成的学习和想探索德国的冲动。**

## 4.2 三大核心乐趣

### 1. 每一天都要做取舍

时间、金钱、体力、学习、人际关系之间互相牵制。

### 2. 学习不是填数值，而是解锁世界

学习能力提高后，玩家可以：

- 看懂更多邮件和账单；
- 与 NPC 深入对话；
- 解锁更多地点任务；
- 参加更多社团和活动；
- 获得父母更多信任和资助。

### 3. 探索、社交与成长互相推动

地图探索不是单纯收集，探索会带来：

- 语言任务；
- 文化知识；
- 美食成就；
- NPC 共同经历；
- 学习素材；
- 生活压力和费用支出。

# 5. 游戏世界与故事设定

## 5.1 基础设定

主角是一名中国学生，初三毕业后前往德国慕尼黑附近学习和生活。

推荐学校设定为：

> **德国国际学校 / 双语学校 / 国际课程学校**

这样可以合理解释：

- 为什么地点在德国；
- 为什么主角需要大量学习德语；
- 为什么课程体系可以包含 A-levels；
- 为什么主角会同时使用中文、英语和德语；
- 为什么学校里有德国学生、国际学生和中国学生。

## 5.2 时间跨度

长期设定是三年制成长线：

### Year 1：适应期

- 德语 A1 → A2；
- 学校生活适应；
- 基础课程衔接；
- 认识朋友；
- 学会独立生活；
- 初步探索德国城市。

### Year 2：成长与分化期

- 德语 A2 → B1；
- A-levels / 国际课程学习加深；
- 学业压力增加；
- 社团、兴趣、旅行、关系线展开；
- 更多德国城市解锁。

### Year 3：升学与选择期

- 德语 B1 → B2；
- A-levels 高阶课程；
- 大学申请；
- 未来方向选择；
- 重要 NPC 关系结局。

# 6. 核心玩法循环

## 6.1 每日循环

```text
起床
→ 查看手机 / 邮箱 / 日历 / 信箱
→ 早餐 / 买早点 / 自己做饭
→ 通勤
→ 上课
→ 午餐 / 社交
→ 下午课程 / 体育 / 社团
→ 放学后选择：回家、学习、探索、打卡、购物、球场、博物馆
→ 晚上做饭 / 作业 / 复习 / 视频通话
→ 状态结算
→ 睡觉进入下一天
```

## 6.2 长期循环

```text
学习
→ 练习
→ 作业
→ 测试
→ 成绩反馈
→ 父母信任变化
→ 生活费变化
→ 探索空间变化
→ 新地点 / 新关系 / 新任务解锁
```

## 6.3 探索循环

```text
发现地点
→ 查看路线和花费
→ 决定是否前往
→ 支付交通 / 门票 / 餐饮成本
→ 触发打卡 / NPC / 知识卡 / 美食成就
→ 获得奖励或压力
→ 影响学习、预算、关系和父母信任
```

## 7.1 MVP 内容范围

时间：30 天  
产品形态：单机版优先  
地图：慕尼黑游戏化像素地图

# 9. 路线服务策略

## 9.1 路线服务定义

路线服务不是地图显示系统，而是根据真实道路网络计算：

- 从 A 到 B 怎么走；
- 距离多少；
- 预计时间多少；
- 交通方式；
- 路线折线 polyline / geometry。

地图显示仍然使用游戏自己的像素地图。

## 9.2 MVP：预设路线

MVP 阶段不接路线 API，不自建路线服务。

使用人工配置路线：

```json
{
  "from": "home",
  "to": "school",
  "mode": "walking",
  "minutes": 18,
  "cost_eur": 0,
  "energy_cost": 5,
  "route_points": [[300, 620], [420, 580], [530, 500]]
}
```

优点：

- 成本为零；
- 稳定可控；
- 适合验证玩法；
- 不依赖第三方 API。

## 9.3 内测 / 正式早期：第三方 API + 缓存

当 MVP 成立后，引入第三方路线 API。

策略：

```text
第一次查询路线 → 调用第三方 API
返回 distance / duration / polyline
写入 route_cache
后续同样 from/to/mode → 直接读取缓存
```

候选服务：

1. Mapbox Directions API；
2. GraphHopper API；
3. OpenRouteService；
4. Google Routes API；
5. 高德海外 Routes API 作为备选。

## 9.4 不采用方向

MVP 不做：

- 自建全德国 OSRM；
- 全德国实时路线计算；
- 全德国地图瓦片自由缩放；
- Google Map 像素化。

# 13. 父母资助系统

## 13.1 系统定位

父母资助是游戏经济压力的重要来源。

核心逻辑：

```text
学习好
→ 父母更信任
→ 生活费稳定或增加
→ 可以探索更多德国城市和地点

学习差 / 预算混乱
→ 父母信任下降
→ 生活费减少
→ 只能压缩餐饮、旅游、社交
→ 可能进入危机生活线
```

## 13.2 父母信任评分

父母信任取决于：

- 学业成绩；
- 作业完成率；
- 德语进步；
- 老师反馈；
- 预算管理；
- 是否按时沟通；
- 账单是否处理；
- 是否自理生活；
- 是否乱花钱；
- 是否长期不回复消息。

## 13.3 资助等级

- Level 0：危机资助；
- Level 1：基础资助；
- Level 2：正常资助；
- Level 3：信任资助；
- Level 4：奖励资助。

## 13.4 失败与补救

不直接 Game Over，而是进入风险链：

```text
余额不足
→ 饮食变差
→ 体力下降
→ 学习效率下降
→ 成绩下降
→ 父母信任下降
→ 资助减少

```

补救剧情包括：

- 和父母视频通话解释；
- 向老师求助；
- 申请学校支持；
- 取消旅行；
- 做更严格预算；
- 进入省钱挑战。

# 24. Agent 设计规范

## 24.1 总原则

所有 Agent 必须遵守：

1. 不直接发布内容，只生成 draft 或 needs_review；
2. 所有真实世界数据必须保留 source_record；
3. 所有价格必须带 retrieved_at、valid_from、valid_to、confidence；
4. 所有坐标必须保留来源；
5. 所有图片必须确认授权；
6. 用户评价不能大段复制，只能摘要；
7. 课程内容必须映射学习目标；
8. 输出必须是结构化 JSON；
9. 不允许编造真实价格、菜单、营业时间或票价；
10. 必须经过合规检查和人工审核。

## 24.2 标准 Pipeline

```text
create_job
→ fetch_sources
→ normalize
→ deduplicate
→ enrich
→ transform_to_game_schema
→ validate
→ compliance_check
→ create_review_task
→ human_review
→ publish
```

- 数据库：50-100GB；
- 对象存储：100-500GB；
- Redis：1-2GB；
- Agent Worker：按需运行；
- 路线服务：第三方 API + 缓存。

## 27.3 全德国扩展

如果只扩内容：

- 更多城市；
- 更多 POI；
- 更多餐厅；
- 更多课程；
- 更多图片；

主要增加：

- 数据库；
- 对象存储；
- CDN；
- Agent 离线处理。

只有在需要全德国实时路线、自建地图瓦片、大规模实时 AI 时，才需要明显增强服务器。

# 28. 风险点与应对策略

## 28.1 内容生产成本高

应对：

- 模板化系统；
- Agent 导入；
- 人工审核；
- 数据驱动；
- MVP 控制边界。

## 28.2 地图 / 图片 / 价格数据合规

应对：

- 使用 OSM / 开放数据优先；
- 保留来源；
- 不复制未授权图片；
- 不复制商业平台评论原文；
- 价格设置有效期和 confidence；
- 人工审核后发布。

## 28.3 AI 成本与稳定性

应对：

- 只在关键场景使用 AI；
- 常规 NPC 使用固定脚本；
- 语音任务缓存；
- AI Gateway 统一管理；
- 固定任务规则兜底。

## 28.4 可玩性不足或过于教育化

应对：

- 30 天 MVP 小闭环；
- 每天必须有资源取舍；
- 学习解锁世界；
- 失败也有剧情；
- 周末作为玩法高潮；
- 打卡、做饭、社交、预算形成多线乐趣。

## 28.5 未成年人社交与安全

应对：

- 默认单机优先；
- 轻联网用模板消息；
- 不开放自由私聊作为早期功能；
- 审核机制；
- 举报 / 屏蔽；
- 恋爱内容健康适龄。

# 29. 不采用或暂缓的方案

以下方案不进入 MVP：

- 高德海外路线作为默认路线方案；
- 自建全德国 OSRM；
- 全德国实时地图瓦片；
- 所有 NPC 实时 AI 语音；
- 开放世界 MMO；
- 自由私聊；
- 未经授权的真实餐厅图片和评论；
- 一开始做完整三年内容；
- 一开始做全德国城市；
- 一开始完整做所有 A-levels 科目。

# 30. 项目一句话总结

**gagaToday 是一款以真实德国数据为基础、用像素 RPG 方式表现的留学生活模拟游戏。玩家在有限的时间、金钱、体力和语言能力下，学习课程、处理账单、经营关系、探索德国、完成打卡、练习语言，并通过成长获得更多生活自由。**

最终目标不是做一个“德国地图游戏”，而是做一个：

> **可体验、可学习、可规划、可扩展的德国留学生活模拟平台。**
