# 迁移建议 — ArtAsset 新模型

**批次**：munich_20260621_initial_audit
**日期**：2026-06-21
**提交方**：美术资产智能体
**接收方**：架构 agent / 主协调 agent

## 背景

Content Schema (docs/CONTENT_SCHEMA.md) 当前定义了 14 个核心数据模型：

PlayerState, Location, Route, Npc, DialogueScenario, DailyEvent, Task, Message, Mail, Bill, Lesson, Homework, Test, Recipe, Achievement, ActionLogEntry

但**没有** ArtAsset 模型。美术资产目前散落在 `assets/{characters,scenes,ui,references}/` 目录中，文件名 + 目录结构是唯一的"元数据"，无法被 content system 引用、查询或审核。

## 建议新增 ArtAsset 模型

### 字段定义

```json
{
  "id": "asset_char_anna_neutral",
  "asset_path": "assets/characters/anna/anna_neutral.png",
  "asset_category": "character",
  "asset_subtype": "portrait",
  "usability": "placeholder",
  "spec": {
    "width": 896,
    "height": 1200,
    "color_palette": "PICO-8 + custom",
    "format": "png",
    "transparent": true,
    "anti_aliasing": "off",
    "shadow_style": "hard_1px",
    "aspect_ratio": "6:8",
    "file_size_kb": 524,
    "md5": "可选，用于去重"
  },
  "style_guide_ref": "docs/ART_ASSETS.md#1-角色立绘",
  "linked_entities": {
    "npc_id": ["npc_anna_bakery_placeholder"],
    "location_id": ["loc_munich_bakery"],
    "task_id": [],
    "dialogue_id": [],
    "achievement_id": [],
    "city_id": [],
    "bill_id": []
  },
  "ai_generation_prompt": "16-bit pixel art ...",
  "ai_reference_image": "可选，记录同角色其他表情的引用",
  "confidence": 0.95,
  "last_verified_at": "2026-06-21T13:00:00Z",
  "notes_zh": "中文备注",
  "source_records": ["source_ai_matrix_20260621"],
  "review_status": "draft"
}
```

### 必填字段

- `id`：snake_case
- `asset_path`：项目内相对路径
- `asset_category`：character / scene / ui / city_badge / map / reference
- `asset_subtype`：portrait / background / button / icon / dialogue_box / etc
- `usability`：usable / placeholder / needs_review / reference / rejected
- `spec.format`：png / jpg / webp
- `source_records`：来源 ID 列表
- `review_status`：draft / needs_review / reviewed / approved / published

### 可选字段

- `spec` 内部除 `format` 外都可选
- `style_guide_ref`：引用 `docs/ART_ASSETS.md` 哪一节
- `linked_entities`：关联 NPC / Location / Task / Dialogue / Achievement / City / Bill
- `ai_generation_prompt` / `ai_reference_image`：AI 生成时记录
- `confidence`：0-1
- `last_verified_at`：ISO8601
- `notes_zh`：中文备注

### 字段枚举

**`asset_category`**：

- `character`：角色立绘
- `scene` / `background`：场景背景
- `ui`：UI 元素（按钮、对话框、图标等）
- `city_badge`：城市徽章
- `map`：地图
- `reference`：参考图
- `font`：字体文件
- `audio`：音频（未来扩展）

**`asset_subtype`**（与 category 组合）：

- character: portrait / full_body / sprite_sheet / expression_neutral / expression_smile / etc
- scene / background: interior / exterior / cityscape / landscape
- ui: button / icon / dialogue_box / panel / frame / feedback_card / loading
- city_badge: round / shield / square
- reference: style / subject / character / scene / general

**`usability`**：

- `usable`：可直接进游戏
- `placeholder`：临时占位，等正式稿替换
- `needs_review`：待人工审核
- `reference`：仅作风格 / 视觉方向参考，不进游戏
- `rejected`：已弃用，不进游戏

**`color_palette`**：

- `PICO-8`
- `Endesga 16`
- `Sweetie 16`
- `Lospec_XX`（其他 Lospec 调色板）
- `Munich_warm`（项目自定义：#D4A847 啤酒金 + #3066BE 巴伐利亚蓝 + 阿尔卑斯白）
- `Berlin_legacy`（柏林旧调色板，仅用于已生成资产）
- `custom`（项目自定义）
- `unknown`（用户提供的图，无法判断）

## 文件位置

```text
frontend/src/content/munich/art_assets.json
```

或按可用性拆为：

```text
frontend/src/content/munich/art_assets_usable.json
frontend/src/content/munich/art_assets_reference.json
frontend/src/content/drafts/art/munich_YYYYMMDD_批次/art_assets.draft.json
```

**建议**先放 draft，待人工审核后由主协调 agent 决定是否迁入 published。

## 兼容性影响

- 前端 import：需修改 `frontend/src/components/` 下引用 assets 的地方，从 `import xxx from '@/assets/...'` 改为通过 content system 查询 `art_assets.json` 后加载
- Game Core：无需直接引用
- Phaser：scene loader 可通过 `art_assets.json` 动态加载

## 迁移步骤（建议）

1. **Phase 0（已完成）**：本次任务已建立 manifest + 4 个分类清单 + 1 个请求清单 + 1 个合规清单（全部 draft）
2. **Phase 1**：架构 agent 在 Content Schema 增加 ArtAsset 模型（§X.ArtAsset）
3. **Phase 2**：将 `art_asset_manifest.draft.json` 转为符合 schema 的 `art_assets.json`（draft → reviewed 流程由主协调 agent 决定）
4. **Phase 3**：前端 component 改造，从 content system 读取 art_assets
5. **Phase 4**：QA agent 加 content schema 校验脚本

## 拒绝 ArtAsset 模型的后果

- 美术资产继续散落在 `assets/` 目录
- 无法被 content system 引用、查询
- 无法用脚本批量生成（必须手写文件名）
- 跨项目复用困难

## 接受 ArtAsset 模型的好处

- 美术资产成为 first-class data，可被脚本管理
- AI 生成后可自动写入 manifest
- 跨地点 / 跨场景复用更容易
- 版权 / 来源 / 可用性审核更系统
